## วิธีเล่น

```powershell
npm run serve      # ใน ExerciseMode
# เล่นจริง:   http://localhost:8000/web/exercise-play.html
# ไล่ปัญหา:   http://localhost:8000/web/exercise.html
```

ตั้งการ์ด ชก jab ให้สุดแขนแล้วดึงกลับ ระบบนับเป็นหนึ่งหมัดแล้วให้เกรด
PERFECT / GOOD / OK ตามความคล้ายท่าต้นแบบของครูมวย

**`exercise-play.html`** — แผ่นงานขนาดคงที่ **1300x2800** (จอตั้งแนวตั้ง) ย่อให้พอดี
หน้าต่างด้วย `transform: scale()` ใน JS บนจอมีแค่ กล้อง / เวลา / จำนวนหมัด /
ความแม่นยำ / feedback และปุ่มเดียว เปลี่ยนขนาดได้ที่ `STAGE_W` `STAGE_H`
(มีที่เดียว ทั้ง CSS และ JS อ่านจากตัวเดียวกัน)

ภาพกล้องใช้ `object-fit: contain` ไม่ใช่ `cover` — ช่องกล้องเป็นแนวตั้งแต่กล้องให้ภาพ
แนวนอน ถ้า cover จะเหลือภาพแค่ ~46% ของความกว้าง คือครอปแขนที่เหวี่ยงออกข้างทิ้ง
ผู้เล่นมองไม่เห็นแขนตัวเองทั้งที่โมเดลยังเห็น (โมเดลอ่านจากเฟรมเต็มเสมอ)
แลกกับแถบดำบน-ล่าง

**`exercise.html`** — เหมือนกันแต่มีแผงด้านข้าง คอมโบ และสรุปท้ายรอบ

| query string | ใช้ได้ที่ | ทำอะไร |
|---|---|---|
| `?seconds=90` | ทั้งสองหน้า | ความยาวรอบ |
| `?free=1` | ทั้งสองหน้า | ไม่จับเวลา (`exercise-play` นับเวลาขึ้น) |
| `?debug=1` | `exercise.html` | โชว์ระยะดิบ เฟรมต้นแบบที่แมตช์ cosine fps สถานะแขน |
| `?strict=1` | `exercise.html` | ไม่ลองเทียบท่าแบบพลิกซ้ายขวา (บังคับข้างมือ) |

## มาจากไหน

เดิมคือ `main.py` — FastAPI WebSocket ที่รับ keypoint จากแอปมือถือไปคำนวณบนเซิร์ฟเวอร์
ตอนนี้ย้ายมาคำนวณบนเครื่องผู้เล่นทั้งหมดเหมือนโหมดต่อสู้ จึงไม่ต้องเปิดเซิร์ฟเวอร์ Python

```
train_model.py                       เทรน Siamese 99 -> 32 -> 16
scripts/export_web.py                -> tfjs_build/jab_siamese/bundle.json
web/exercise-scorer.js               คำนวณฝั่งเบราว์เซอร์ (port จาก main.py)
scripts/compare_exercise.mjs         พิสูจน์ว่า JS == Python
```

ไม่ได้ใช้ TF.js เพราะ base network มีแค่ 3,728 พารามิเตอร์ และ embedding ของท่าต้นแบบ
คำนวณไว้ล่วงหน้าใน `bundle.json` แล้ว เหลือแค่คูณเมทริกซ์สองครั้งต่อเฟรม

## สามอย่างที่ต้องรู้ก่อนแก้ค่าในนั้น

**1. ชุดท่าต้นแบบต้องเหลือแค่เฟรมที่หมัดยืดสุด**

`jab_ref_video.npy` มี 119 เฟรม ครอบทั้งวงจร การ์ด → ออกหมัด → กลับการ์ด
ถ้าให้คะแนนแบบ "ใกล้เฟรมไหนก็ได้ในคลิป" การยืนตั้งการ์ดเฉย ๆ จะได้ **100%**
(วัดได้ระยะ 0.001) เพราะในคลิปก็มีเฟรมตั้งการ์ดอยู่

`export_web.py` จึงคัดเหลือ 22 เฟรมที่ข้อศอกเหยียด ≥ 150° แล้วเฟรมตั้งการ์ด
ได้ระยะ 1.36 ตามที่ควรเป็น — `scripts/compare_exercise.mjs` มีเทสต์คุมข้อนี้ไว้

**2. ด่าน cosine — อย่าปิด**

เหมือน `minPresenceRatio` ของโมเดล LSTM: embedding ของ Siamese เสื่อมนอกช่วงข้อมูล
ที่เทรน ป้อน noise สุ่มหรือเฟรมที่หาคนไม่เจอ (ศูนย์ทั้งแถว) เข้าไป ReLU ตัดเหลือ 1-2 มิติ
แล้วไปอยู่ใกล้ embedding ของเฟรมต้นแบบที่เสื่อมแบบเดียวกัน ได้ระยะ 0.004
= **"เหมือนท่าครูมวย 99%" ทั้งที่ไม่มีคนในเฟรม**

cosine บนพิกัดดิบแยกสองกรณีนี้ขาด — ท่าคนจริง 0.57-1.00 · noise 0.10 · ศูนย์ 0.00
เกณฑ์ขั้นต่ำ 0.5 อยู่ใน `bundle.json`

**3. ตัวเลขเปอร์เซ็นต์ใจกว้างกับทุกหมัดที่ยืดแขน**

ระยะของโมเดลสะท้อน "แขนเหยียดแล้วหรือยัง" มากกว่าสะท้อนรายละเอียดฟอร์ม
วัดจากชุด X1: หมัดที่ยืด ≥150° ได้ระยะ median 0.013 (≈96%) จังหวะกลางทาง 0.024
ท่าตั้งการ์ด 0.43 ขึ้นไป (0%)

เกรดจึงไม่ได้ดูเปอร์เซ็นต์อย่างเดียว — `JabScorer.update()` ต้องเห็นวงจรครบ
(การ์ด → ยืด ≥150° → กลับการ์ด) และข้อมือต้องมีความเร็วถึงเกณฑ์ ถึงจะนับเป็นหนึ่งหมัด
ถ้าอยากให้คะแนนละเอียดกว่านี้ ต้องเก็บท่าต้นแบบเพิ่มและเทรนใหม่ ไม่ใช่ขยับเกณฑ์
