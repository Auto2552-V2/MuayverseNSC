# Python client — webcam → MediaPipe → LSTM → WebSocket → Unity

ทางเลือกของเส้นทางเบราว์เซอร์ สำหรับ **ทดสอบบนเดสก์ท็อปเท่านั้น**
ตัวที่จะไปอยู่บนมือถือจริงยังเป็น `web/pose-detector.js` ใน WebView (ดู CLAUDE.md)

```powershell
# 1. เปิด Unity scene SparringMode แล้วกด Play  (PoseWebSocketServer รอที่ 8787)
# 2. รันตัวนี้
.venv\Scripts\python.exe py_client\pose_ws_client.py
```

| ไฟล์ | หน้าที่ |
|---|---|
| `pose_ws_client.py` | ทั้งหมดอยู่ในไฟล์เดียว — กล้อง, MediaPipe, โมเดล, ตัวกรอง, ส่ง WebSocket |
| `pose_action.tflite` | สร้างอัตโนมัติจาก `../pose_action.h5` ครั้งแรกที่รัน ลบทิ้งได้ |

## ตัวเลือกที่ใช้บ่อย

```powershell
--preview                    # เปิดหน้าต่างกล้อง เห็นโครงกระดูก + แถบความมั่นใจ + fps
--preview-scale 1.0          # ขนาดหน้าต่างพรีวิว (ค่าเริ่มต้น 0.5 = 320x240)
--no-ws                      # พิมพ์ผลเฉย ๆ ไม่ต่อ Unity
--video ..\Video\JAB.mp4     # ใช้คลิปแทนกล้อง
--max-frames 400             # หยุดหลัง N เฟรม
--threshold 0.6              # ลดเกณฑ์ความมั่นใจ
--camera 1                   # กล้องตัวที่สอง
```

## ของสามอย่างที่ต้องตรงกับตอนเทรน ไม่งั้นโมเดลตอบผิดอย่างมั่นใจ

1. **พลิกภาพก่อนเข้า MediaPipe** (`cv2.flip`) ไม่ใช่พลิกพิกัดทีหลัง — ดู CLAUDE.md หัวข้อ Mirror
   คลิปที่บันทึกมาแบบพลิกไว้แล้วให้ใส่ `--no-flip`
2. **aspect ต้องมาจากขนาดภาพจริง** โค้ดอ่านจากเฟรมให้เอง
   ตอนพัฒนาเคยตั้ง 4:3 ตายตัวแล้วเอาไปรันคลิป 16:9 ผลคือ jab กับ cross
   กลายเป็น hook ด้วย confidence 0.95+ โดยไม่มี error อะไรเลย
3. **feature มาจาก `scripts/pose_features.py`** ไม่คัดลอกมาไว้ที่นี่ จะได้ไม่มีสำเนาที่เพี้ยนได้

`--preview-scale` ย่อ **เฉพาะหน้าต่างที่แสดง** ภาพที่ป้อนเข้า MediaPipe ยังเป็น 640×480 เสมอ
อย่าไปย่อภาพที่เข้าโมเดลเพื่อให้เร็วขึ้น — ความละเอียดต่ำลงทำให้ landmark แกว่ง
และต่างจากตอนเก็บข้อมูลเทรน

## ที่วัดไว้แล้ว

| เรื่อง | ผล |
|---|---|
| ความแม่นบน `MP_Data_Diag/session_3` (ชุดทดสอบที่โมเดลไม่เคยเห็น) | **93.3%** ตรงกับที่เอกสารระบุ |
| TFLite เทียบกับ Keras | ตรงกันที่ `atol=1e-4` |
| ความเร็ว inference | TFLite 3.6 ms/เฟรม (Keras `predict()` 154 ms — ช้ากว่า 40 เท่า) |
| ความเร็วรวมที่ 640×480 | ~20 fps (MediaPipe 46 ms + inference 3.6 ms) |
| สาย WebSocket | ทดสอบกับ `scripts/mock_unity_ws.mjs` ผ่าน ส่ง/รับ/กรอง conf ได้ถูก |

### ⚠ ข้อควรระวังเรื่อง fps

window 36 เฟรมถูกออกแบบไว้ที่ ~28 fps (≈1.3 วินาที) ถ้าเครื่องรันได้ 20 fps
window เดียวกันจะกินเวลา 1.8 วินาที คือ "ยืด" ท่าออกเทียบกับตอนเทรน
ความแม่นตอนชกจริงจึงอาจต่ำกว่า 93.3% — ยังไม่ได้วัดกับกล้องจริง

ถ้าเจอว่าอ่านท่าไม่ค่อยออก ให้ดู fps ที่บรรทัด `[done]` ก่อนเป็นอันดับแรก

## ข้อจำกัด

- รองรับ client เดียว ถ้าหน้าเว็บต่อ 8787 อยู่ ต้องปิดก่อน
- `PoseWebSocketServer` ผูกกับ `127.0.0.1` เท่านั้น ต้องรันบนเครื่องเดียวกับ Unity
- ไม่ได้ส่งข้อความ `status` (nocamera/nopose) ที่เส้นทางเบราว์เซอร์ส่ง
  ฝั่ง Unity จึงไม่ขึ้นเตือนเรื่องกล้องเมื่อใช้ทางนี้
